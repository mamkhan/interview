# Architecture Decision Records

Eight records were drafted and reviewed 2026-09-07 (all Accepted, three amended at the review); ADR-009 and ADR-010 followed as the first domain was built.

| ADR | Outcome | Decision as accepted |
|---|---|---|
| [ADR-001](adr-001-repository-and-solution-structure.md) | Accepted | One repository, one solution; domains as isolated module groups; isolation rules enforced by architecture tests |
| [ADR-002](adr-002-packaging-and-deployment.md) | Accepted, amended | Deployment granularity is each domain's own concern; each domain carries its own build and deployment pipeline and deploys autonomously; Metering & Consumption may run several units (highest scale), simpler domains may run one; amended 2026-10-06: the V1 reader is a platform on-premises worker on the proof of concept's VM |
| [ADR-003](adr-003-data-access.md) | Accepted | Dapper everywhere; SqlBulkCopy for bulk paths; startup-owned schema; explicit temporal typing; transaction-per-message unit of work; named revisit trigger |
| [ADR-004](adr-004-messaging-and-consistency.md) | Accepted, amended | Service Bus backbone with sessions, idempotency, acknowledge-last, dead-letter discipline, outbox; amended to make correlation propagation, structured logging, OpenTelemetry observability and the retry taxonomy explicit |
| [ADR-005](adr-005-application-architecture.md) | Accepted | Domain/Application/Infrastructure layering; CQRS as handler separation with projections; plain handlers with a written mediator trigger; event sourcing only for the two ledgers |
| [ADR-006](adr-006-iac-and-environments.md) | Accepted, amended | Two-layer Terragrunt model: a platform stack creates the shared resources; each domain owns and applies its own infrastructure stack through its own pipeline; tiers as data per environment; Aspire local-only; amended 2026-10-06: the V1 reader's SQL login is the one exception to Entra-only access; amended 2026-10-07: one unit per resource type serving every environment, its instances as YAML files, one state per environment and type |
| [ADR-007](adr-007-testing.md) | Accepted, amended | Classicist TDD; frozen-literal expectations; acceptance tests gate deploys; amended 2026-10-12: three tiers (unit, integration, acceptance), the AppHost boot tier removed, the acceptance suite run locally before every push, each pipeline runs only its own tests |
| [ADR-008](adr-008-coding-standards-and-repository-hygiene.md) | Accepted, amended | Warnings as errors; central package management; domain-language naming; one-architecture-doc policy; amended to trunk-based development (main always releasable, branches live hours, incomplete work lands dark) |
| [ADR-009](adr-009-azure-resource-naming.md) | Accepted | Azure resource naming: org, environment, domain code, type and instance segments composed in the Terragrunt units |
| [ADR-010](adr-010-domain-first-repository-layout.md) | Accepted, amended | Domain-first layout: each domain folder holds its code, infrastructure, pipeline, solution and AppHost; `platform/` holds the shared assets; slices by capability inside modules; hosts as the only runnable projects; supersedes ADR-001's layout; amended 2026-09-25 to `Domain/`, `Application/Features/` and `Infrastructure/` halves with roles registered as `Add<Feature>Application`/`Add<Feature>Infrastructure` pairs; amended 2026-10-06: Pricing & Rate Cards in Growth, and a domain's LocalGraph may reference another's |
